# redscaresu/github-actions ships the per-repo files as `templates/` (dependabot.yml, gitleaks.toml, SECURITY.md, pre-commit, hooks.mk; no scorecard.yml, Scorecard is the bundle's reusable `.github/workflows/scorecard.yml`), uses its own copies (dogfood, HLD:234), and its README shows the security.yml caller and the scorecard.yml caller, the inputs, the check names, the copy list and the versioning rules, so the SHA that becomes v1.0.0 already documents itself (HLD Goals 3, 5; Design §1 templates, §2).

**Done when:** In redscaresu/github-actions `main`: `ls templates/` is exactly `dependabot.yml gitleaks.toml SECURITY.md pre-commit hooks.mk` (no scorecard.yml); each starts with `template: <name>` as a comment in its own syntax (`#` on line 1; line 2 in pre-commit after the shebang; `<!-- -->` in SECURITY.md) and carries no version (decision 4). `templates/dependabot.yml`: gomod + github-actions, weekly, grouped, no auto-merge, no mention of org-wide credentials. `templates/gitleaks.toml`: `[extend] useDefault = true`, allowlist paths `go\.sum$` only. `templates/SECURITY.md`: Reporting a vulnerability (private vulnerability reporting first, then `<email>` with `[security] <repo>:` subject), Handling of credentials (placeholder), Maintainer review (the HLD:278-284 rule verbatim: every diff touching `.github/`, `.gitleaks.toml`, `.golangci.yml` or adding `#nosec` / `//nolint` / `//gosec:disable` / `zizmor: ignore`, and every fork PR touching them, is read by the owner before merge), and 'a key seen on any public branch is rotated, never only removed'. `templates/pre-commit`: `gitleaks protect --staged --no-banner`, exits non-zero with a message naming gitleaks when it is not on PATH. `templates/hooks.mk`: a `hooks` target that copies pre-commit to `$(shell git rev-parse --git-path hooks)/pre-commit` and `chmod +x` (works in a worktree). The repo's own `.gitleaks.toml` and `SECURITY.md` are the templates filled in for github-actions; `.github/dependabot.yml` differs from the template only in its header. README.md: the caller block (triggers push main / pull_request / weekly schedule; job id `security`; `uses: redscaresu/github-actions/.github/workflows/security.yml@<sha> # vX.Y.Z`; `permissions: {contents: read, security-events: write}`), and the `.github/workflows/scorecard.yml` caller (`on:` push to main and a weekly schedule only; `permissions: {}`; one job `security`, `name: security`; `uses: redscaresu/github-actions/.github/workflows/scorecard.yml@<sha> # vX.Y.Z`; `permissions: {contents: read, id-token: write}`; never in a workflow that runs on pull_request), the only file that grants `id-token: write`, with the note that it publishes only on a push or scheduled run on the default branch of a public repo; the inputs table (the seven security.yml inputs: `codeql-languages`, `dependency-review-fail-on` and booleans `zizmor`, `gitleaks`, `govulncheck`, `codeql`, `dependency-review`), the five security.yml check names plus `security / scorecard` from the scorecard.yml caller and that a skipped gate reports success, the five-file copy list with the consumer header rule `template: <name> @<version>`, Versioning (MAJOR/MINOR/PATCH per HLD:216-218, SHA + tag comment pin, no moving `v1`, tag cut by hand from a green dogfood), and the `## Scorecard` answer from the probe (REFUTED, https://github.com/redscaresu/github-actions/actions/runs/38005404874). `zizmor .github/` 0; dogfood green on `main` after merge; `gh api .../tags` still `[]`.
