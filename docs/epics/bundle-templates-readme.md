# redscaresu/github-actions ships the per-repo files as `templates/` (scorecard.yml, dependabot.yml, gitleaks.toml, SECURITY.md, pre-commit, hooks.mk), uses its own copies (dogfood, HLD:234), and its README shows the one-job caller, the inputs, the check names, the copy list and the versioning rules, so the SHA that becomes v1.0.0 already documents itself (HLD Goals 3, 5; Design §1 templates, §2).

**Done when:** In redscaresu/github-actions `main`: `ls templates/` is exactly `scorecard.yml dependabot.yml gitleaks.toml SECURITY.md pre-commit hooks.mk` (scorecard.yml absent only if decision 6 moved it into the bundle); each starts with `template: <name>` as a comment in its own syntax (`#` on line 1; line 2 in pre-commit after the shebang; `<!-- -->` in SECURITY.md) and carries no version (decision 4). `templates/scorecard.yml`: `permissions: read-all`, job `analysis` named `Scorecard analysis` with `security-events: write` + `id-token: write`, `publish_results: true`, triggers push:main + weekly schedule + branch_protection_rule and no pull_request, no workflow-level env/defaults, all actions SHA-pinned. `templates/dependabot.yml`: gomod + github-actions, weekly, grouped, no auto-merge, no mention of org-wide credentials. `templates/gitleaks.toml`: `[extend] useDefault = true`, allowlist paths `go\.sum$` only. `templates/SECURITY.md`: Reporting a vulnerability (private vulnerability reporting first, then `<email>` with `[security] <repo>:` subject), Handling of credentials (placeholder), Maintainer review (the HLD:273-277 rule verbatim: every diff touching `.github/`, `.gitleaks.toml`, `.golangci.yml` or adding `//nosec` / `zizmor: ignore`, and every fork PR touching them, is read by the owner before merge), and 'a key seen on any public branch is rotated, never only removed'. `templates/pre-commit`: `gitleaks protect --staged --no-banner`, exits non-zero with a message naming gitleaks when it is not on PATH. `templates/hooks.mk`: a `hooks` target that copies pre-commit to `$(shell git rev-parse --git-path hooks)/pre-commit` and `chmod +x` (works in a worktree). The repo's own `.gitleaks.toml` and `SECURITY.md` are the templates filled in for github-actions; `.github/dependabot.yml` differs from the template only in its header. README.md: the caller block (triggers push main / pull_request / weekly schedule; job id `security`; `uses: redscaresu/github-actions/.github/workflows/security.yml@<sha> # vX.Y.Z`; `permissions: {contents: read, security-events: write}`), the inputs table, the five `security / *` check names and that a skipped gate reports success, the six-file copy list with the consumer header rule `template: <name> @<version>`, Versioning (MAJOR/MINOR/PATCH per HLD:216-218, SHA + tag comment pin, no moving `v1`, tag cut by hand from a green dogfood), and the `## Scorecard` answer from the probe. `zizmor .github/` 0; dogfood green on `main` after merge; `gh api .../tags` still `[]`.

**Out of scope:** Any change to security.yml or the gates (bundle-gates). Tagging. A drift check (HLD:69). A TypeSafe gitleaks rule (HLD:204-205).

**Constraints:** Templates are copies and may drift; no mechanism (HLD:69,197-199). Headers carry no version in the shared repo; consumers add `@<version>` at copy time (decision 4). SECURITY.md follows goldfinger's structure (goldfinger SECURITY.md:3,17,46) plus Maintainer review (decision 7). The README caller must match what bundle-gates built (inputs, permissions). Local check as fixed in bundle-gates. Everything here lands before the SHA adopt-bundle-private pins, so the tag carries it.
